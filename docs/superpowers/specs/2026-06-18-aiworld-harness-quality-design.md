# AI World Harness 품질 개선 설계

> 작성일 2026-06-18 · 대상 `v2/aiworld-harness` · 상태: 설계(미착수)

## 북극성 (최우선)

**결과물(생성 콘텐츠)의 퀄리티가 모든 것에 우선한다.** 말도 안 되는 산출물을 만들지 않는 것이 제1원칙. 검증기·프롬프트·UX 어떤 것을 고치든, 결과물의 사실성·일관성·자연스러움을 **깎으면 안 된다**. 의심스러우면 더 보수적인 쪽(사람 확인 플래그 유지)을 택한다.

## 진단 (실데이터 5 run / 197 컴포넌트 근거)

통과율이 0%에 가까운 진짜 원인은 콘텐츠가 0점이어서가 아니라 **채점 파이프라인이 오염**되어서다.

| 컴포넌트 | 통과 | 실패 | 미검증(timeout) |
|---|---|---|---|
| material | 0 | 30 | 28 |
| practice | 0 | 46 | 27 |
| quiz | 2 | 38 | 29 |

3대 오염원:
1. **Glossary 부분문자열 오탐** — `forbidden:["단답"]` ⊂ 정답 `"단답형"`, `["체크리스트"]` ⊂ `"실전 체크리스트"` → 정상 표현이 매번 플래그. (`glossary_validator.py:36` 순수 substring 매칭). 약 29건.
2. **Schema 예시 마커 오탐** — 예시를 6개 마커(`예)`,`예를 들어`,`1)`,`2)`,` 또는 `,`예시)`)로만 카운트 → 생성기가 `예:`,`가령`,`①②`,markdown 등 다른 형태로 쓰면 0개로 잡힘. (`schema_validator.py:241`). 약 27건.
3. **검증 타임아웃** — 루브릭 검증 타임아웃 180s(`config.py:38`), `max_tokens=12000`. GPT 판정이 한도 초과 → 84개 컴포넌트가 아예 미검증.

추가 요구: 생성 콘텐츠의 **언어가 AI 번역투** → Humanize KR(im-not-ai) 패턴으로 한글화 개선. **단계별 UX/UI**도 폴리시.

## 품질 가드레일 (전 워크스트림 공통)

모든 변경은 아래를 만족해야 착수·머지된다.

- **검증 약화 금지**: 오탐을 줄이되, 진짜 결함(사실오류·일관성붕괴·서식위반)을 놓치게 만들면 안 된다. 오탐 수정은 "정상 표현을 통과시키는" 것이지 "위반을 통과시키는" 게 아니다.
- **의미 보존 (한글화)**: 숫자·고유명사·직접인용·날짜·약어는 원문 그대로. Humanize KR 원칙 차용 — 수정량 30% 초과 시 경고, 50% 초과 시 중단.
- **회귀 검산**: W1·W2는 기존 197 컴포넌트로 before/after 오탐 카운트 비교. W3~W5는 새 run 1개로 검산하되, 사람이 샘플 스팟체크 후 수용.
- **단계 분리**: 워크스트림 단위로 끊어 진행, 대량 동시수정 금지, 각 단계 build·동작 확인, 커밋은 기능당 하나.

## 워크스트림

### W1 · Glossary 부분문자열 오탐 수정 (비용 0)
- **변경**: `glossary_validator.py` — forbidden 매치 span이 **임의의 canonical 표현 span에 완전 포함**되면 위반 제외. (예: `단답` 매치가 `단답형` 범위 안 → skip. 단, `분류하기`처럼 forbidden이 canonical보다 길어 완전포함이 아니면 정상 플래그 유지.)
- **검산**: 기존 quiz/material 197건 재검증 → `단답`/`체크리스트` 오탐 ~29→0, 진짜 위반(`객관식`,`주관식` 등)은 유지 확인.
- **리스크**: 낮음. 화이트리스트성 제외라 위반 누락 위험 적음.

### W2 · Schema 예시 마커 탐지 정렬 (비용 0)
- **변경**: ① `schema_validator.py:241` 마커 집합 확장(`예:`,`가령`,`이를테면`,`①~⑩`,`- ` 리스트 등) + 의미 기반 보강. ② 생성기 프롬프트에 **표준 예시 표기 1종**으로 출력하도록 통일(탐지와 생성 동시 캘리브레이션).
- **검산**: 기존 material/practice 재검증 → 마커 오탐 27건 급감, 진짜 "예시 없음"은 유지.
- **리스크**: 중. 확장이 과하면 "예시 있음" 오인 가능 → 보수적으로 확장.

### W3 · 검증 타임아웃 신뢰성 (새 run 검산)
- **변경**: `config.py`/`base.py`/`orchestrator.py` — 타임아웃 현실화, 판정 payload 축소(불필요 컨텍스트 제거), 타임아웃 시 1회 재시도. `revalidate`가 이미 timeout 상태를 복구 대상에 포함하므로 연계.
- **검산**: 새 run 1개에서 `validation_timeout` 0에 수렴.
- **리스크**: 중. 타임아웃만 늘리면 run 시간↑ → payload 축소·재시도와 병행.

### W4 · 한글화 예방 주입 (새 run 검산)
- **변경**: `backend/agents/*.py` 생성기 프롬프트에 Humanize KR **S1·S2 금지패턴**을 규칙으로 주입:
  - 번역투(through→직접표현, 이중피동, "~가 있다"), 과잉 영어병기, 기계적 "첫째/둘째/셋째" 나열, AI 상투어("결론적으로","주목할 만한"), 어미 리듬 단조, 군더더기 수식어, 과잉 헤징, 접속사 남발, 형식명사 과다("~라는 사실"), 시각장식 남용.
  - **의미 보존 가드레일 동봉**: 숫자·고유명사·인용 불변.
- **검산**: 새 run 콘텐츠를 사람이 읽어 "사람이 쓴 것 같은가" + 사실 보존 확인.
- **리스크**: 중. 과교정으로 정보 손실 위험 → 가드레일로 차단, 스팟체크 필수.

### W5 · 프롬프트/루브릭 취향 재튜닝 (새 run 검산, 마지막)
- **변경**: W1~W4로 신호가 깨끗해진 뒤, 남은 BORDERLINE/품질 이슈를 보고 `agents/*`·`rubric-v1.yaml` 미세조정.
- **검산**: 새 run + 사람 리뷰. 합격 기준 재설정.
- **리스크**: 낮음(앞 단계가 선행되어야 의미 있음).

### W6 · 단계별 UX/UI 폴리시 (콘텐츠 품질 다음 우선순위)
- **범위**: 5탭 stepper 흐름(Control→Execution→Review→Deploy)의 단계 인지·다음액션 유도, Review 3-pane에서 플래그 우선순위(상/중/하) 시각화, 빈/로딩/에러 상태 명확화.
- **안티패턴 제거**(CLAUDE.md 기준): pill 3개+ 동시노출, 색상 3종+, 과도 radius/shadow, 떠다니는 장식. "토스 디자이너라면 뭘 먼저 지울까?" 기준.
- **검산**: 브라우저 실동작(browse/playwright) before/after 스크린샷.
- **리스크**: 낮음(기능 불변, 표현만).

## 실행 순서 & 게이트

```
W1 ─▶ W2 ─▶ [게이트: 기존 데이터 오탐 회귀 검산, 비용 0]
        └─▶ W3 ─▶ W4 ─▶ [게이트: 새 run 1개, 비용 ~$1~3, 사람 스팟체크]
                          └─▶ W5 ─▶ [게이트: 새 run + 리뷰]
                                     └─▶ W6 (UX, 병행 가능)
```

- **새 run 비용 발생 시점은 W3 진입 직전에 별도로 사용자 승인**받는다.
- W1·W2는 무비용·확정버그 → 즉시 착수.

## 가정 / 미해결

- **가정**: 기존 5 run 데이터가 현재 프롬프트·루브릭 버전과 동일 계열(캘리브레이션 유효). 다르면 W1·W2 회귀 검산은 방향성 참고로만.
- **미해결**: GPT-5.4 판정 타임아웃의 정확한 병목(모델 지연 vs payload 크기) — W3 착수 시 1차 측정으로 확정.
- **범위 제외**: 신규 컴포넌트 타입 추가, 인증/배포 인프라(README 로드맵 별건).
